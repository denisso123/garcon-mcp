## Findings

### 1. medium — The ownership fix reintroduces double-counting for other ambiguous bottles

[src/ingredients.ts:177](/private/tmp/claude-501/-Users-denisso-Documents-work-blankpage-fixmeadrink-marketing-seo/d887e153-c878-4b3e-8f7d-31ccbd68ad24/scratchpad/review/mcp3/src/ingredients.ts:177), particularly aliases at lines 39–40 and 83.

Only entries in `ONE_BOTTLE` now receive conditional treatment. Every other alias becomes definite ownership:

```ts
const names = lookup(ALIASES, term)
return names ? resolved(term, names) : null
```

For example:

```ts
scotch: ['Blended scotch whisky', 'Single malt scotch whisky']
```

**Reproduction through the exported Worker**, using `ingredients: ["scotch"]` and a recipe requiring both catalogue names:

```json
{
  "have": ["Blended scotch whisky", "Single malt scotch whisky"],
  "missing": [],
  "can_make_now": true
}
```

At `5bce4e3`, this alias was constrained by `one_of`; the new implementation removes that constraint. Different Scotch types can serve distinct recipe roles, as in the IBA’s [Penicillin recipe](https://iba-world.com/iba-cocktail/penicillin/). Treating an acceptable substitution as definite ownership also contradicts the new output schema.

**Fix:** Review all multi-name bottle aliases, including `scotch` and `orange liqueur`. Put uncertain variants into `could_be`. If substitutions are intentional, represent them separately instead of reporting both ingredients as definitely owned.

### 2. medium — Link refusal triggers another attempt to open the destination

[src/widget.ts:185](/private/tmp/claude-501/-Users-denisso-Documents-work-blankpage-fixmeadrink-marketing-seo/d887e153-c878-4b3e-8f7d-31ccbd68ad24/scratchpad/review/mcp3/src/widget.ts:185).

```js
return deps.request('ui/open-link', { url: url }).then(function (result) {
  if (result && result.isError) fallback(url);
}, function () { fallback(url); });
```

The installed [MCP Apps definition](/Users/denisso/Documents/work/blankpage/fixmeadrink/garcon-mcp/node_modules/@modelcontextprotocol/ext-apps/dist/src/app.d.ts:963) explicitly defines `isError: true` as including a blocked domain or user cancellation.

**Reproduction:** resolving the bridge request with `{ isError: true }` invoked the fallback opener with the same URL. `test/widget.test.ts:207` explicitly asserts this incorrect behavior.

The four-second timeout at `src/widget.ts:214` also triggers fallback while a person may still be considering Claude’s confirmation modal. Claude documents that custom connectors always show this modal and dismissal cancels the request. [Claude external-link documentation](https://claude.com/docs/connectors/building/mcp-apps/external-links)

This behavior predates the redesign but remains in the reviewed code.

**Fix:** Treat denial and cancellation as final. Select a supported opener using negotiated capabilities before sending the request. Do not automatically retry navigation after a timeout; offer an explicit retry or copyable URL.

### 3. low — Ranking termination assumes unique ingredients, but scoring counts rows

[src/ranking.ts:220](/private/tmp/claude-501/-Users-denisso-Documents-work-blankpage-fixmeadrink-marketing-seo/d887e153-c878-4b3e-8f7d-31ccbd68ad24/scratchpad/review/mcp3/src/ranking.ts:220), also `src/service.ts:261`.

The upper bound counts distinct normalized catalogue names:

```ts
const haveCeiling = definiteNames(recognised).size
```

But `compareWithBar()` preserves repeated required rows, and `rankMatches()` scores `have.length`.

**Reproduction through the Worker:**

- Bar: `["vodka"]`, limit 1.
- First eight recipes: `["Vodka", "Chilled water", "Saline solution 4:1"]`.
- Ninth recipe: `["Vodka", "Vodka"]`.

The Worker fetched eight details, returned the first recipe and omitted `partial`. Comparing all nine with its own comparator selects the ninth because its `have.length` is two.

This is a reproducible mismatch between the bound and comparator. **I found no repeated required names in the 250 saved recipe samples**, so I am not claiming demonstrated impact on the current live catalogue.

**Fix:** Deduplicate normalized ingredient requirements for ownership and ranking, while preserving recipe quantities separately. Alternatively, use an upper bound valid for row-count scoring. Add a boundary test that compares the optimized result with exhaustive ranking.

### 4. low — Expired calls can still succeed through memory and completed-promise caches

[src/upstream.ts:175](/private/tmp/claude-501/-Users-denisso-Documents-work-blankpage-fixmeadrink-marketing-seo/d887e153-c878-4b3e-8f7d-31ccbd68ad24/scratchpad/review/mcp3/src/upstream.ts:175), also line 211.

Deadline checks live in `stage()` and `attempt()`. These paths bypass both:

```ts
if (hot !== undefined) return hot as T | null
```

```ts
return pending as Promise<T | null>
```

**Reproduction:**

```text
deadlineMs: 100
load /warm successfully
wait 140 ms
load /warm again → success

new instance, deadlineMs: 30
wait 60 ms
load the memory-cached /warm → success
```

This does **not** recreate the previous indefinitely pending I/O problem. It means the advertised operation deadline is still not enforced uniformly.

**Fix:** Check expiry before returning an existing promise or memory entry. Keep the stage-level timeouts for pending work.

### 5. low — The unchanged widget URI can retain a renderer that hides new result semantics

[src/widget.ts:28](/private/tmp/claude-501/-Users-denisso-Documents-work-blankpage-fixmeadrink-marketing-seo/d887e153-c878-4b3e-8f7d-31ccbd68ad24/scratchpad/review/mcp3/src/widget.ts:28).

```ts
export const WIDGET_URI = 'ui://ask-garcon/cocktail-list-v1.html'
```

The old and new renderers use the same URI, although the new output introduces `depends_on` and `partial`.

**Reproduction:** executing the `5bce4e3` renderer with a current conditional-vermouth result produced an empty `Missing:` status and displayed neither the condition nor the partial-result indication.

OpenAI explicitly treats the resource URI as a cache key and instructs developers to change it for breaking HTML, JavaScript or CSS changes. [OpenAI UI documentation](https://developers.openai.com/plugins/build/chatgpt-ui)

README says this server has not been deployed, so this is a release/versioning defect, not evidence that existing production users are affected.

**Fix:** Publish this renderer as `cocktail-list-v2.html` and update resource registration, tool metadata and fixtures together.

## Requested regression checks

**Origin policy.** I found no evidence supporting a claim that this policy breaks ordinary ChatGPT or Claude traffic. Anthropic documents that remote connectors connect from its cloud across Claude clients. OpenAI documents its integration egress ranges. Widget tool calls use the host bridge; the MCP Apps lifecycle forwards them from the host to the server. They are not direct iframe `fetch()` calls carrying the iframe’s browser Origin. [Claude networking](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp), [OpenAI egress](https://developers.openai.com/api/docs/guides/ip-addresses), [MCP Apps lifecycle](https://github.com/modelcontextprotocol/ext-apps/blob/main/docs/overview.md)

However, those documents **do not guarantee the exact outbound `Origin` header or its permanent absence**. The comment at `src/index.ts:38` presents an inference as fact. Real-host header capture remains necessary before claiming compatibility is verified. The current widget makes no tool calls itself.

**Ranking and `partial`.** The frequent partial result is expected:

```ts
if (worst.comparison.missing.length > 0 ||
    worst.comparison.dependsOn.length > 0) return true
```

An unchecked recipe could still be complete because preview missing counts include optional ingredients and garnishes. Without their counts, a tighter missing-ingredient bound would be speculation.

Consequently, frequent `partial: true` is principally a **search-quality and request-cost limitation**, not a correctness defect by itself. It honestly discloses that the cap stopped the proof. Obtaining required-ingredient summaries upstream would improve this more safely than weakening the stop rule. Completeness is also only relative to the candidates returned by the upstream endpoint.

**Widget escaping, CSP and theme.** No additional defect confirmed:

- Server-derived text is escaped; recipe and image URLs have anchored host restrictions.
- Embedded configuration escapes `<`; the supplied `assetOrigin` is internal configuration, not request input.
- CSP metadata allows both actual asset origins. Font CORS headers exist. ChatGPT’s resource omits custom-font declarations and preloads.
- Executing the complete embedded script confirmed initialization, dark-to-light theme updates, safe-area values, escaped errors and cancellation.
- Public-page interpolation uses fixed application values; I found no new request-derived injection path.

## Verdict

**Approve with changes.** I would not approve this as-is, but it needs targeted fixes rather than a rewrite.

The five changes that matter most:

1. Apply conditional ownership consistently to ambiguous bottle aliases.
2. Respect host link denial and user cancellation.
3. Make ranking bounds and ingredient-count semantics agree.
4. Enforce deadline expiry on cache fast paths.
5. Version the changed widget resource so cached renderers cannot hide conditions or truncation.
