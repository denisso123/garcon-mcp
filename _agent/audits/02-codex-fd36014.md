1. **high — Unbounded body parsing happens before rate limiting.**  
   [src/index.ts:69](/private/tmp/claude-501/-Users-denisso-Documents-work-blankpage-fixmeadrink-marketing-seo/d887e153-c878-4b3e-8f7d-31ccbd68ad24/scratchpad/review/mcp/src/index.ts:69), also lines 114–116.

   `await request.clone().json()` reads and parses the entire body before checking `IP_LIMITER`. Rejected callers can repeatedly consume memory and CPU, including the buffering introduced by cloning the body.

   **Evidence:** A request containing 5 MiB of padding produced this execution order:
   ```text
   parsed 5242880 padding bytes
   reject IP
   ```
   The installed MCP server has a default 4 MiB request limit in `@modelcontextprotocol/server/dist/index.mjs:252`; this preliminary read bypasses that protection.

   **Fix:** Check the IP limit before reading the body. Apply a streaming byte limit, validate content type, and parse once. Pass the parsed body through the handler’s supported request options.

2. **medium — Cold requests duplicate upstream work and can exhaust the shared budget.**  
   [src/upstream.ts:132](/private/tmp/claude-501/-Users-denisso-Documents-work-blankpage-fixmeadrink-marketing-seo/d887e153-c878-4b3e-8f7d-31ccbd68ad24/scratchpad/review/mcp/src/upstream.ts:132), `src/service.ts:249–257`.

   The cache stores completed values only. Concurrent misses each execute `await load()`. The main and low-proof pools overlap and fetch their details concurrently.

   **Evidence:** Ten concurrent identical `get()` calls caused ten fetches. One recipe present in both pools was fetched twice. A valid 25-ingredient call, with one transient 503 per endpoint, consumed all 60 upstream permits and failed.

   There is no per-invocation upstream budget. On Workers Free, the documented limit is 50 subrequests; the paid allowance is higher. I did not measure Worker CPU usage or establish the deployment’s plan. [Cloudflare limits](https://developers.cloudflare.com/workers/platform/limits/)

   **Fix:** Fetch the union of candidate IDs once, coalesce requests within each invocation, and enforce a per-call budget that includes retries. Prevent concurrent cold fills from consuming the entire shared allowance.

3. **medium — The per-user quota trusts caller-controlled identity.**  
   [src/index.ts:73](/private/tmp/claude-501/-Users-denisso-Documents-work-blankpage-fixmeadrink-marketing-seo/d887e153-c878-4b3e-8f7d-31ccbd68ad24/scratchpad/review/mcp/src/index.ts:73), also line 117.

   ```ts
   const subject = body?.params?._meta?.['openai/subject']
   if (subject && !(await allowed(env.CALLER_LIMITER, `sub:${subject}`)))
   ```

   This public endpoint does not authenticate who supplied the subject. Omitting it skips the limiter; changing it selects another bucket.

   **Evidence:** After the subject bucket rejected a request with 429, the same request without `openai/subject` returned 200. The IP and upstream limits remain, so this bypass specifically defeats the advertised per-user allowance.

   **Fix:** Treat the subject as advisory unless its sender is verified. Enforce an anonymous cost allowance independently of supplied metadata; require trusted identity assertions for a guaranteed per-user quota.

4. **medium — Retry handling ignores upstream cooldowns and misses body-read failures.**  
   [src/upstream.ts:179](/private/tmp/claude-501/-Users-denisso-Documents-work-blankpage-fixmeadrink-marketing-seo/d887e153-c878-4b3e-8f7d-31ccbd68ad24/scratchpad/review/mcp/src/upstream.ts:179), also lines 202–206.

   Every first 429/5xx gets a fixed 400 ms retry. `Retry-After` is ignored. Separately, `response.json()` sits outside the retry `try/catch`, so a connection failure or timeout during body consumption bypasses the advertised retry and `UpstreamError` conversion.

   **Evidence:**
   ```text
   429 with Retry-After: 120 → retry after 401 ms
   200 with body TimeoutError → one attempt, raw DOMException
   ```

   **Fix:** Include body consumption in the protected attempt. Respect `Retry-After`, use bounded backoff with jitter for transient failures, cancel discarded response bodies, and impose an overall operation deadline.

5. **medium — An optional recommendation failure discards a valid primary answer.**  
   [src/service.ts:255](/private/tmp/claude-501/-Users-denisso-Documents-work-blankpage-fixmeadrink-marketing-seo/d887e153-c878-4b3e-8f7d-31ccbd68ad24/scratchpad/review/mcp/src/service.ts:255), also lines 267–270 and 355–357.

   Main results and optional low-proof recommendations share a failure boundary. A failed fallback catalogue fetch throws after usable cocktail results have already been obtained. Premium recipe lookup similarly depends on successfully fetching free alternatives.

   **Evidence:** A fixture returned a valid, immediately makeable vodka recipe; the optional catalogue returned 503. The entire tool returned `UpstreamError`, losing the recipe.

   **Fix:** Preserve successful primary results. Handle optional recommendation failures separately and report their unavailability. Never describe an unavailable recommendation search as an empty successful search.

6. **medium — Cache keys omit the upstream identity.**  
   [src/upstream.ts:110](/private/tmp/claude-501/-Users-denisso-Documents-work-blankpage-fixmeadrink-marketing-seo/d887e153-c878-4b3e-8f7d-31ccbd68ad24/scratchpad/review/mcp/src/upstream.ts:110), also lines 118 and 136.

   Keys contain the method, path and body, but omit `baseUrl`. Both the module-level cache and Cache API namespace therefore conflate the explicitly supported production/staging overrides.

   **Evidence:**
   ```text
   Upstream(baseUrl=one).get('/same') → {source:'one'}
   Upstream(baseUrl=two).get('/same') → {source:'one'}
   Fetches to two: 0
   ```

   **Fix:** Include the normalized upstream base URL and cache schema version in both cache keys. This is cross-upstream cache contamination; I found no user-controlled URL path that directly enables remote cache poisoning.

7. **medium — Ambiguous ingredient aliases become simultaneous ownership.**  
   [src/ingredients.ts:79](/private/tmp/claude-501/-Users-denisso-Documents-work-blankpage-fixmeadrink-marketing-seo/d887e153-c878-4b3e-8f7d-31ccbd68ad24/scratchpad/review/mcp/src/ingredients.ts:79), `src/service.ts:243`.

   ```ts
   vermouth: ['Sweet vermouth', 'Dry vermouth']
   ```
   Every expansion is flattened into the owned-ingredient set. Alternative interpretations become ingredients the user supposedly has together.

   **Evidence:** With only `"vermouth"`, comparing a recipe requiring both variants returned:
   ```json
   {"have":["Sweet vermouth","Dry vermouth"],"missing":[]}
   ```

   **Fix:** Separate true synonyms from ambiguous variants and substitutions. Resolve ambiguity or retain uncertainty; an unspecified bottle must not establish ownership of both ingredients.

8. **medium — Truncation happens before the ranking information exists.**  
   [src/service.ts:249](/private/tmp/claude-501/-Users-denisso-Documents-work-blankpage-fixmeadrink-marketing-seo/d887e153-c878-4b3e-8f7d-31ccbd68ad24/scratchpad/review/mcp/src/service.ts:249).

   ```ts
   candidatesFromGroups(groups, filters).slice(0, DETAIL_POOL)
   ```
   Only those 12 recipes receive the ingredient comparison that determines the final ranking. API ordering cannot guarantee the same order after optional ingredients, staples and garnishes are excluded.

   **Evidence:** A 13-candidate fixture returned five recipes missing two ingredients each while omitting candidate 13, which required nothing missing.

   **Fix:** Rank using ingredient summaries before truncation, preferably supplied by the backend. Alternatively, use bounded progressive retrieval with an explicit completeness condition. Merely increasing 12 moves the failure boundary.

9. **medium — “Similar” low-proof results include zero-similarity candidates.**  
   [src/service.ts:404](/private/tmp/claude-501/-Users-denisso-Documents-work-blankpage-fixmeadrink-marketing-seo/d887e153-c878-4b3e-8f7d-31ccbd68ad24/scratchpad/review/mcp/src/service.ts:404).

   The code computes an overlap score, sorts it, and retains every candidate:
   ```ts
   .sort((a, b) => b.score - a.score || a.index - b.index)
   .map((entry) => entry.item)
   ```

   **Evidence:** A Coffee/Vodka source returned a Fruity/None alternative with no overlap, accompanied by “share flavours with it.”

   **Fix:** Filter out zero-overlap candidates. If generic low-proof suggestions are desired, expose them as a separate fallback without claiming similarity.

10. **medium — The widget ignores tool errors and cancellation.**  
    [src/widget.ts:160](/private/tmp/claude-501/-Users-denisso-Documents-work-blankpage-fixmeadrink-marketing-seo/d887e153-c878-4b3e-8f7d-31ccbd68ad24/scratchpad/review/mcp/src/widget.ts:160), also line 113.

    It forwards only `params.structuredContent` to `render()`. Server error results contain `isError` and text content, so `render(undefined, …)` returns immediately.

    **Evidence:** Executing the widget script and delivering a valid error notification left “Checking your bar…” unchanged. After a successful render, an error left the previous result displayed. Cancellation also changed nothing.

    The installed Apps SDK defines tool-result notifications as `CallToolResult` and explicitly defines `ui/notifications/tool-cancelled`.

    **Fix:** Handle error and cancellation messages explicitly, clear stale results, and terminate the loading state.

11. **medium — Automated verification can report success while missing production failures.**  
    [test/server.test.ts:6](/private/tmp/claude-501/-Users-denisso-Documents-work-blankpage-fixmeadrink-marketing-seo/d887e153-c878-4b3e-8f7d-31ccbd68ad24/scratchpad/review/mcp/test/server.test.ts:6), `_agent/scripts/smoke.mjs:90`.

    Tests import `createMcpHandler` from `@modelcontextprotocol/server`; production uses `agents/mcp/server` through `src/index.ts`. Routing, origin checks, rate limits, and early response headers are bypassed.

    The smoke script increments `failures` only when `client.callTool()` throws. A normal MCP `{isError:true}` result merely gets logged. All positive tool calls could fail this way and the script would still exit zero.

    **Fix:** Exercise the exported Worker with controlled bindings and upstream fixtures. Give smoke cases explicit expected success/error outcomes and assert meaningful result fields. Include both routes and protocol versions.

12. **low — Unknown input properties are silently discarded.**  
    [src/server.ts:208](/private/tmp/claude-501/-Users-denisso-Documents-work-blankpage-fixmeadrink-marketing-seo/d887e153-c878-4b3e-8f7d-31ccbd68ad24/scratchpad/review/mcp/src/server.ts:208), also the other input schemas.

    Inputs use `z.object()`. In installed Zod 4.6.7, this strips unknown keys; the listed input schema also permits additional properties.

    **Evidence:** `{ingredients:["gin"], strengthh:"zero_or_low"}` passed validation and reached the upstream operation. The intended restriction was silently lost.

    **Fix:** Use `z.strictObject()` for tool arguments and normalize meaningful strings before validating their minimum length.

13. **low — Hand-built 429 responses bypass CORS and JSON-RPC ID validation.**  
    [src/index.ts:42](/private/tmp/claude-501/-Users-denisso-Documents-work-blankpage-fixmeadrink-marketing-seo/d887e153-c878-4b3e-8f7d-31ccbd68ad24/scratchpad/review/mcp/src/index.ts:42).

    Rate-limit responses return before the Agents handler adds CORS headers. They also echo the unvalidated `id` using `id: id ?? null`.

    **Evidence:** Normal responses included `Access-Control-Allow-Origin`; 429 responses did not. A limited request with `id: {"invalid":true}` returned that object as its JSON-RPC response ID.

    **Fix:** Apply a shared response-header policy to early returns, expose `Retry-After` to browser clients, and echo only valid string/number request IDs.

## AI-slop signals

- **Dead exports/data:** `PRIVACY_URL` (`src/site.ts:9`) and `Flavor` (`src/ranking.ts:35`) have no consumers. `RankedMatch.extra` is populated but never read; `requiredCount` is consumed only by a test. `UpstreamError.kind` is never inspected by production code.
- **Needless abstraction:** The unused `extra: T` field creates generic `RankedMatch<T>` plumbing without affecting behavior. Remove the field and generic.
- **Duplicated logic:** `byFewestMissing()` and `rankMatches()` repeat comparator logic. Output shapes are separately maintained as interfaces and Zod schemas.
- **Narrative or misleading comments:** “three cache layers” counts the upstream API itself as a cache (`src/upstream.ts:1`). The retry comment promises network-error handling broader than the implementation. Correct these after fixing behavior.
- **Weak verification:** Description-length assertions prove little. The alternate test handler and smoke script’s exception-only failure counter are the substantive problems above.
- **Defensive redundancy:** `rankMatches()` calls `.slice()` immediately after `.filter()`, although filtering already created a new array.
- **No material naming inconsistency, unnecessary dependency, or nonexistent installed API was established.** The snake_case output fields and camelCase internals form a consistent boundary.

## Verdict

**Approve with changes.** The core separation is understandable, but I would block submission in its current state.

The five changes that matter most:

1. Bound and parse requests once, after cheap ingress checks.
2. Enforce trustworthy abuse limits and per-call upstream budgets; eliminate duplicate fetches.
3. Correct retries and preserve primary results when optional work fails.
4. Fix ambiguous ingredient ownership and ranking before truncation.
5. Test the production Worker path, make smoke failures meaningful, and handle widget error/cancellation states.
